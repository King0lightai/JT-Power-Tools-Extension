v4.9.3 Current May 20, 2026

📧 Email-to-Job (Power User)

  • Every job gets its own email address — BCC it and the email lands on the job's activity feed automatically
    • Open any JobTread job, click the extension icon, and the Account tab shows a copy-friendly address like pat-12345@jtptbills.com (derived from the first 3 letters of the job name + its number). Paste that into a job custom field and the whole team can BCC it on any thread — from Outlook, Gmail, anywhere — and the message auto-posts as an internal-team comment on the job. Subject becomes the comment title; signatures and quoted reply chains get stripped before posting; real file attachments (PDFs, photos) upload to JobTread and attach to the comment
  • Reply threads stay grouped in the JT activity feed
    • When a customer or sub replies to a thread you already landed on the job, the reply nests as a sub-comment under the original instead of becoming a new parallel comment. The Activity feed reads like the actual conversation rather than scattered fragments
  • Forwarded threads explode into one comment per message
    • Forward a long back-and-forth (Outlook or Gmail) to the job address and the parser splits it into individual messages — your intro lands as the parent comment, each historical message as a nested reply with its own From / Sent / Subject header. No more single-comment-with-everything-crammed-into-it
  • Admin opt-in toggle in the portal
    • New Email to Job section in the portal sidebar (admin / owner only). One company-wide toggle to enable or disable the feature for your whole license. Disabling stops new mail and new provisioning instantly but leaves existing parked emails and history intact — soft kill, not destructive. Use it to keep sensitive jobs (legal disputes, etc.) on a human-approved workflow if needed

🤖 Automations (Power User — bring your own agent)

  • Subscribe your own AI or backend to Power Tools events via signed webhooks
    • New Automations tab in the portal lets you register an HTTPS endpoint that receives signed POSTs when an event fires for one of your orgs. First event shipping: bill.received — the moment a vendor email lands in your bills inbox, your agent gets pinged. Build a Cloudflare Worker / Lambda / anything-reachable-on-https that auto-categorizes, matches POs, or routes to QuickBooks. Payloads sign with HMAC-SHA256 so your agent can verify it actually came from us. Per-connection delivery log surfaces the last 50 attempts so you can answer “did my agent get this?” without ssh'ing into logs

🦊 Firefox: Extension Restored

  • All features now load on Firefox — not just Text Formatter and a handful of others
    • The Firefox manifest was missing four script entries that Chrome had. Because the extension's loader waited for every feature module to register before starting any of them, a single missing module silently killed the entire extension on page load — every feature stayed dormant until you toggled it off and back on in the popup. The four missing scripts have been added, AND the loader is now defensive: if any feature module fails to load (now or in the future), only that one feature is skipped and the rest of the extension keeps working

📋 Forms — Admin Toggle Moved to Portal (Power User)

  • Forms is now a company-wide admin decision instead of a per-user popup toggle
    • The Forms on/off switch moved out of the extension popup and into the JT Power Tools Portal — mirroring the Email-to-Job pattern. One owner or admin flip applies to the whole team. New Company-wide toggle card at the top of the portal's Forms section shows the current state, a count of active vs. archived templates, and a single switch. Disabling hides the per-job drawer + blocks new template / instance writes; every existing template and filled-instance row stays intact, so flipping back ON restores the full feature set (soft kill, not destructive). Backfill on rollout: any license with at least one non-archived template stays enabled automatically — you don't have to touch the toggle if you're already using Forms

✉️ Per-Job Email Card — Visual Polish

  • The email card in the extension popup got a cleaner, more focused look
    • Cleaner card with the address itself promoted to a single bordered “hero” container, an icon-only copy button tucked inside it (instead of a giant orange Copy button parked beside it), and the status info (Auto-post ON / OFF, count of received emails) rendered as compact pill chips that read at a glance. Copy feedback flips the icon for 1.5s with a green tint instead of swapping “Copy” ↔ “Copied!” text. Dark mode and Custom Theme still work via the existing color tokens

Added a third button to the existing template toolbar (now Expand · Templates ▾ · Settings) that toggles the textarea between the default height and ~70% of the viewport — about 3.5× more room before scrolling kicks in. Icon flips between “expand” and “collapse” arrows; keyboard accessible (Enter / Space)

✨ New Features

  • Document Sort — Sortable Column Headers on Job › Documents (Free)
    • Click any column header on the Job › Documents table (Name / Account / Subject / Status / Amount) to sort. Each click cycles asc → desc → back to JobTread's original order, so undoing a sort is one click away
    • Force-loads every row on first click — the Documents table lazy-loads as you scroll, which means a naive sort would only reorder rows you've already seen. We auto-scroll the table to the bottom in 100ms ticks until JobTread stops loading new rows, then sort the complete dataset. Your scroll position is saved before the load and restored after, so you land back where you started instead of pinned to the bottom of the page
    • Smart parsers per column — Name and Account sort by the bold primary line; Subject sorts text with empty values pushed to the end; Status uses a sensible enum order (draft < pending < payable < approved < paid) with the document date as a tiebreaker so within "draft" you still get a date-ordered slice; Amount parses the currency string properly (handles negatives like credit memos)
    • Skips the force-load entirely when the table already fits on screen — short job histories sort instantly with no scroll bounce
  • Open the Popup as a Pinned Side Panel
    • New sidebar icon in the popup header re-opens the same UI in Chrome's native side panel via chrome.sidePanel. Useful for keeping the Theme builder, Tweaks list, or Quick Notes visible while working in JobTread — the panel stays pinned next to the page instead of dismissing on every blur. Toolbar click still opens the regular popup by default; the side panel is opt-in per click. Hidden on Firefox (no sidePanel API there) and inside the side panel itself (no point in re-opening). 🔒 Security & Auth

  • Portal Login Works Again for All Password Formats
    • A subtle JavaScript scoping bug in a recent security pass put portal sign-in into a state where the password-verification function would throw before it could compare hashes — manifesting to users as “Invalid email or password” even when credentials were correct. The bug only affected accounts using the newer PBKDF2 hash format (most active accounts). Fixed; sign-in works as expected
  • Extension Popup Auth Endpoints Work Through Captcha
    • A Cloudflare Turnstile captcha was recently added to the four portal auth endpoints (login / register / forgot-password / reset-password) to deflect bot traffic. The captcha widget can't render inside a Chrome extension popup, which meant pinned-extension users were getting Missing captcha token errors on every sign-in. The server now recognizes requests coming from the extension origin (via the Origin header, which the browser sets and JavaScript can't spoof) and skips the captcha gate for those — per-IP rate limiting still applies, but captcha is no longer required from inside the extension
  • Password-Reset Email Links Now Use URL Fragments

  • Transactional Emails Restyled to Match the New Portal Design
    • Invite emails, system-invite emails, and password-reset emails now render in the portal's light-mode design — cream background, white card with warm border, solid orange CTA pill, Anton heading font with Impact fallback for the “POWER TOOLS” wordmark. ✨ New Features

  • MCP Server — 2 New Forms Tools (Power User)
    • jobtread_forms_list_for_job + jobtread_forms_upsert_instance — thin wrappers over the Forms data layer, Power User tier-gated. Bring the total tool count to 45 and close the AI-fills-handwritten-form loop end-to-end
  • MCP Server — headerDepth Opt-Out for Job & Financial Context (Power User)
    • The job header (10 customFields + folder list + customer block + location block) used to ship on every jt_job_context / jt_financial_context response regardless of include — on a tight include: ["budget"] query it was 75% of the payload
    • New headerDepth parameter: 'full' (default, backward-compatible), 'minimal' (returns just { id, name, jobNumber } so callers retain identity context for downstream tool calls), 'none' (omits the job section entirely). Estimated ~9× token reduction on a 3-item budget query going full → none
    • Edge cases handled: include: ['job'] + headerDepth: 'none' rejected with a clear error before any Pave call fires; empty include + headerDepth: 'none' falls back to the default sections minus 'job'
  • MCP Server — include: ["snapshots"] Opt-In for Document Comparisons (Power User)
    • Surfaces document-snapshot costGroup roots grouped by their owning document — useful for "compare HIA-snapshot pricing against live budget" workflows. Distinct from the pre-existing budgetBackups section (user-saved backup history). Each entry: { documentId, rootCostGroupId, rootName, rootCreatedAt }
    • Bonus diagnostic fields liveRootCount and snapshotRootCount added to summary responses for callers debugging snapshot-tree growth
  • MCP Server — Per-Array Truncation for jt_raw_query (Power User)
    • Pave responses are mostly nested arrays of node objects, but the worker's >10 KB truncation was a head/tail JSON-string slice that lost the MIDDLE of those arrays — exactly where the data callers wanted typically lived
    • New default for >10 KB responses without intent: walk the response structure recursively, shorten any array longer than 5 entries to the first 5 + a { _truncated: true, droppedCount, fullLength } sentinel. Adds a top-level _truncationApplied block describing what got trimmed and why, so callers can see at a glance and refine their query
    • Falls back to the legacy head/tail string slice with strategy: 'fallback-string-slice' when per-array truncation isn't enough (response is wide-not-deep — many fields per node). Cycle-safe via WeakSet. intent still bypasses both paths — relevance filter + indexing run unchanged
  • MCP Server — Indexed-Section Labels Surfaced in Intent Responses (Power User)
    • When intent triggered FTS5 indexing, the response said "use ctx_search" without naming the keys — agents had to guess section path syntax (job.costGroups.nodes[3]) and repeatedly miss
    • Response now includes an _indexed block listing the exact { key, preview } pairs the FTS5 store has for this query, plus the source label and a usage hint. When index: false is supplied, the in-memory relevance filter still runs and the response gets a _filtered block instead — same shape, but flagged as not-searchable post-hoc. Both blocks cap at 30 sections + a { _truncated, droppedCount, fullLength } sentinel
  • MCP Server — Pre-Flight Validation for ctx_batch & jt_raw_query (Power User)
    • ctx_batch now pre-validates every command's tool field before dispatching ANY of them — missing/non-string tool rejects the whole batch with "Command at index N missing required field 'tool'" so the caller can fix the malformed entry instead of hunting through "Unknown tool: undefined" errors
    • jt_raw_query gains an index: boolean parameter (default true) — when false AND intent is supplied, the response is filtered by relevance via a new in-memory scorer but NOT indexed into the FTS5 knowledge base, saving the indexing latency + storage cost for one-shot queries
    • jt_raw_query now pre-flight-walks every $.size in the query payload — any connection with size > 100 returns a clear path-pointed error ("Connection size cap exceeded: <path>.size = <value>...") before the Pave call fires, so callers don't have to manually trace which nested connection triggered the generic 400. All three pre-validation paths verified by tests confirming Pave call count = 0 on bad input

🛡️ MCP Correctness Fixes

  • Live-Tree Budget Resolution — jt_job_context & jt_financial_context (P1)
    • Empirically verified against Cyr Addition (a real document-heavy job): JobTread snapshots every document's line items into a parallel costGroup tree on the same job — a job with 1 HIA + N invoices has N+1 parallel "SCOPE OF WORK" trees. Previous name-based dedup with most-items + newest-createdAt tiebreak was returning items: [] with hasMore: true on document-heavy jobs (cursor advanced but never yielded data) and overstating summary.itemCount by ~9× — 1072 items reported, 113 actually live
    • Replaced the heuristic with resolveLiveTree (filters costGroup.document === null client-side) + fetchLiveItems per live root via descendentCostItems. New shared module _budget.js since both context avenues need the same helpers. The misleading "totals include all Pave cost items" note was removed because it no longer applies — the response only contains live-tree items now
  • assertLiveCostGroup Defensive Helper for Budget Writes (P1)
    • Three jt_budget_write ops — createGroup, deleteGroup, importCatalogGroup — accepted caller-supplied parent/target costGroup IDs without validating they were on the live tree. A caller passing a snapshot-tree ID (an HIA's frozen costGroup, an invoice's line-item record) would land writes inside the document's snapshot, corrupting frozen contract data. Quiet, hard-to-detect, and dangerous
    • New helper runs a single Pave query for { costGroup.$.id, document.id } and throws with a path-pointed error if document is non-null. Wired as a defensive pre-flight on the three ops; fail-fast before any mutation. Stale avenues/job-context.parity.js diagnostic harness with hardcoded fixtures from the pre-91ea83ab dedup query shape was deleted in the same commit — not auto-run, not imported, no remaining references
  • Save Engine Permanent-vs-Transient Error Classification (Forms)
    • Pre-fix: 401/403/404 errors had the dirty fields re-added to the queue, so the next keystroke would retry the doomed request — infinite retry on a permanent auth/tier failure. Now classifies 401/403/404 as permanent: skip the re-add, surface meta.permanent: true + status to the caller so the status pill renders "Auth error" / "Permission denied" / "Form deleted" / "Save failed (N)" instead of "Offline — will retry"
